# Вектор

Менеджер задач, который отличает работу от занятости.

Горизонты те же, что в Google Tasks: «Сегодня», «Неделя», «Месяц», «Потом». Главное отличие в том, что каждая задача проходит фильтр по главной цели. Приложение следит, чтобы день уходил на задачи, которые двигают дело вперёд, и помогает убрать остальное.

## Идея

Легко неделями работать много и при этом почти не двигаться: время уходит на задачи, которые только похожи на работу. Косвенные задачи приятнее прямых. Они проще, результат виден сразу, и после них кажется, что день прошёл продуктивно. Вектор делает эту подмену заметной.

**1. Сначала цель.** При первом запуске ты пишешь одну главную цель через результат, который можно посчитать. Например, «10 новых клиентов в месяц». Цель всегда видна вверху экрана, и все задачи оцениваются по ней.

**2. У каждой задачи есть тип.** Без типа задачу не добавить. На каждую приложение задаёт вопрос: «Если сделать только это, ты приблизишься к цели?»

| Тип | Что значит | Пример для цели «10 клиентов в месяц» |
| --- | --- | --- |
| Прямая | Сама по себе приносит деньги или двигает цель | Позвонить тёплым клиентам, отправить КП |
| Косвенная | Помогает, но результат не сразу и не наверняка | Обновить презентацию, посмотреть вебинар |
| Шум | Не двигает к цели | Разобрать старую почту, сменить тему в редакторе |

Прямые задачи всегда стоят в списке первыми и выделены сильнее. Шум приглушён, и рядом с ним сразу есть кнопка «Отсечь».

**3. «Сегодня» — только главное.** Правила фокуса (лимиты можно поменять в настройках):
- на сегодня не больше 5 задач;
- из них не больше 2 косвенных;
- шум в «Сегодня» не ставится: приложение предлагает отсечь его или отложить в «Потом».

Правило можно обойти кнопкой «Всё равно в „Сегодня“», но каждый раз это осознанное решение.

**4. Радар ловушки.** Приложение замечает, когда ты уходишь в занятость, и говорит об этом прямо:
- закрыто три косвенные задачи подряд, а прямая ждёт;
- за 7 дней прямых задач меньше половины от сделанного;
- прямая задача висит в «Сегодня» несколько дней, то есть её избегают. Совет: разбить её на маленький первый шаг;
- в плане на день нет ни одной прямой задачи.

**5. Разбор 80/20.** По правилу Парето около 20% задач дают 80% результата. Кнопка «Разбор» показывает все открытые задачи по одной карточке, начиная с шума и косвенных. По каждой нужно решить: оставить как прямую, оставить как косвенную, делегировать или отсечь. В конце видно, сколько отсечено и сколько осталось до цели в 80%. Отсечённые и делегированные задачи не пропадают: их можно вернуть.

**6. Хвосты.** Если задача из «Сегодня» не сделана вчера, утром приложение просит решить её судьбу: оставить, перенести в неделю или отсечь. Так невыполненное не копится молча.

**7. Фокус-сессия.** Таймер на одну задачу (25, 50 или 90 минут). Приложение само предлагает первую прямую задачу дня. Время в фокусе считается отдельно для прямых и косвенных задач.

**8. Итоги.** Доля прямых задач за неделю и сравнение с прошлой, график по дням, время в фокусе, сколько отсечено, серия дней подряд с прямой задачей.

## Уведомления

В настройках включаются:

| Уведомление | Когда | Что говорит |
| --- | --- | --- |
| План на день | утром, по умолчанию 09:00 | с какой прямой задачи начать |
| Проверка курса | днём, 13:30 | «Ты сейчас на прямой задаче?», сколько прямых сделано |
| Итог дня | вечером, 20:30 | доля прямых за день, что осталось в «Сегодня» |
| Разбор недели | раз в неделю, по умолчанию воскресенье 18:00 | сколько задач открыто, пора отсечь лишнее |
| Сигнал ловушки | сразу | три косвенные задачи подряд, пока прямая ждёт |
| Напоминание | время из карточки задачи | название задачи |
| Конец фокус-сессии | когда вышло время таймера | отметить результат |

Время каждого уведомления настраивается. Если браузер не разрешил системные уведомления, они показываются внутри приложения.

**В приложении для Android** уведомления стоят в расписании системы на неделю вперёд. Они приходят, даже когда приложение закрыто или телефон перезагружен. Расписание обновляется после каждого изменения задач, поэтому текст всегда про актуальный план.

**В версии для браузера** (и на iPhone) уведомления приходят, пока приложение открыто или свёрнуто. Если закрыть его полностью, браузер не даст ему запуститься в нужное время. Для iPhone это решается нативной сборкой (нужен Mac и аккаунт разработчика Apple) или сервером push-уведомлений.

## Как запустить

Нужен только браузер: приложение написано на чистом JavaScript, сборка не нужна.

```bash
npm start          # локальный сервер на http://localhost:5173
npm test           # тесты логики (Node 20+)
```

Можно запустить и без npm, любым статическим сервером, например `python3 -m http.server 5173`. Открывать файл напрямую (`file://`) нельзя: модули и service worker так не работают.

### Android

Готовый файл: **[vector.apk](https://github.com/submittoarenacloser-hub/Task-manager/releases/latest/download/vector.apk)** (появляется после слияния в `main`).

1. Открой ссылку на телефоне и скачай файл.
2. Открой его. Android попросит разрешить установку из этого источника (браузера или «Файлов») — разреши.
3. При первом включении уведомлений в настройках приложения Android спросит разрешение. На Android 12+ приложение предложит ещё «точное время», чтобы напоминания не опаздывали.

Новая версия ставится поверх старой, задачи сохраняются.

Как это устроено. Приложение для Android — тот же код в оболочке [Capacitor](https://capacitorjs.com/). Уведомления идут через плагин `@capacitor/local-notifications`, копия задач сохраняется через «Поделиться». APK собирает GitHub Actions (`.github/workflows/android.yml`) на каждый пуш. Сборка из `main` публикуется в Releases, сборки из других веток лежат в артефактах запуска.

Собрать самому (нужны Android SDK и Java 21):

```bash
npm ci
npm run android:apk      # APK: android/app/build/outputs/apk/release/app-release.apk
npm run android:sync     # или только обновить веб-часть и открыть android/ в Android Studio
```

Подпись. APK подписан ключом `android/app/vector-sideload.keystore` из репозитория. Благодаря этому любая сборка обновляет установленное приложение без потери данных. Для публикации в Google Play нужен свой ключ, который не лежит в открытом доступе: передай его через переменные `VECTOR_KEYSTORE_FILE`, `VECTOR_KEYSTORE_PASSWORD`, `VECTOR_KEY_ALIAS`, `VECTOR_KEY_PASSWORD` (например, из секретов GitHub).

### iPhone и установка из браузера

Приложение устанавливается как PWA и работает без интернета.
- **iPhone (Safari):** «Поделиться» → «На экран „Домой“». Уведомления на iPhone работают только в установленном приложении (iOS 16.4 и новее).
- **Android без APK (Chrome):** открыть сайт → меню → «Установить приложение».

### Публикация на GitHub Pages

В репозитории есть workflow `.github/workflows/pages.yml`: после каждого пуша в `main` он публикует приложение. Один раз нужно включить Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Адрес будет вида `https://<пользователь>.github.io/Task-manager/`.

## Данные

Задачи хранятся только на устройстве (`localStorage`), никуда не отправляются. В настройках есть «Скачать копию» (в Android — «Сохранить копию» через меню «Поделиться») и «Загрузить из файла» (JSON), чтобы перенести задачи на другое устройство.

## Устройство проекта

```
index.html              каркас страницы
manifest.webmanifest    установка на устройство
sw.js                   офлайн-кеш и клик по уведомлению
css/styles.css          стили, светлая и тёмная темы
fonts/                  шрифты Onest и Unbounded (работают без интернета)
android/                проект Android (Capacitor)
scripts/build-native.mjs  сборка www/ для Android
js/
  model.js              типы задач, горизонты, сортировка
  rules.js              правила фокуса для «Сегодня»
  stats.js              статистика и радар ловушки
  schedule.js           когда и что писать в уведомлениях
  focus.js              таймер фокус-сессии
  notifier.js           показ уведомлений
  native.js             Android: системное расписание уведомлений, «Назад», «Поделиться»
  store.js              состояние и сохранение
  app.js                маршруты и отрисовка
  ui/                   экраны: задачи, фокус, разбор, итоги, настройки
tests/                  тесты на node:test
```

Логика (`model`, `rules`, `stats`, `schedule`, `focus`, `store`) не зависит от интерфейса и покрыта тестами. При изменении файлов приложения локально стоит поднять версию кеша в `sw.js` (`CACHE`); workflow публикации делает это сам.
